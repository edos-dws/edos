What to expect

Today Works now, on the stub

  • End-to-end pipeline — context assembly → decision → verification → knowledge, callable over the API.
  • Structured, validated output — every decision conforms to a locked JSON contract; malformed output is never stored.
  • Live streaming (WebSocket) — the frontend can watch an analysis as it happens and subscribe to a project's live event stream, not just poll REST.
  • Prompts wired end-to-end — the generic embedded reasoning prompt is composed and passed through the request path, ready for the real model.
  • Safety behaviour proven — confidence only ever drops on review; nothing freezes automatically.
  • Swagger, Postman & WebSocket docs — the API is explorable, importable, and documented for a frontend.

Next Two human-owned steps

  • Connect the real LLM — choose a provider + API key, swap the stub, author & tune the prompt content (slots are ready).
  • Derive the freeze threshold — run real benchmarks, score them, and set the threshold from data. Until then, autonomous freeze stays off.
How a request flows
Context Engine→ Model Router→ Decision Engine→ Verification→ Freeze gate · off→ Knowledge write-back

Software orchestrates the flow and owns the evidence; the LLM only reasons over what it's handed. That separation is the core design bet. The frontend reaches all of this over REST for request/response and WebSocket for live push (streaming analyses and a per-project event stream).

How it's built

Contract-first

Locked schemas are the source of truth; every engine is built against them.

Test-gated

Every change ships with a test; the build is never left red. CI mirrors the local gate.

Checkpoint-reviewed

Work lands in reviewable slices; the risky calls stay with a human.

Flag, don't guess

Where the spec is silent, it's flagged for a decision — never filled with an invented value.
